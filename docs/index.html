A holistic tooth for drives

The stick is gone. The files are not anyone else's.

DriveTooth puts a password on the files you carry, right where they sit on the USB drive. Lose the drive, send it by courier, plug it into the print shop — nobody reads a thing without you. No account to make, no cloud that holds a copy, no company that can be subpoenaed for your key. Just the drive, and what you type into it.

Real situations

The moments this was written for

Nobody plans to lose a drive. It is the taxi, the reception desk, the courier, the drawer of old hardware. Here is what each of those looks like with the files sealed, and what the person who ends up with the drive can do about it.

local_taxi

The USB stick left in a taxi

Client folders, an ID scan, a spreadsheet with everyone's phone number. Someone picks the stick up, plugs it in at home out of curiosity, and wants names.

check_circle They open the drive and find one hidden-looking folder of unreadable files. No names, no preview, no folder tree, no idea which client anything belongs to. Your password is the only thing that ever knew.

print

The shared office printer and the library computer

You need one document out of a folder of forty. The machine in the corner is not yours, and neither is the memory it keeps of everything that has ever been plugged into it.

check_circle You unlock the drive, copy out the one file you came for, lock it again in a click, and walk away. What stays behind on that computer is ciphertext with no names attached.

local_shipping

The drive mailed to a lawyer, an accountant, a lab

Physical delivery still moves the biggest files. A parcel goes through a sorting facility, a van, somebody's porch, and possibly a claims form.

check_circle The drive arrives, the recipient installs nothing special, and the copy of DriveTooth sitting on the stick opens it with the password you texted them. If it never arrives, nobody else gets a say about what was on it.

health_and_safety

Patient records, journals, evidence, the family photos

Some folders are not embarrassing to lose, they are harmful. A dental chart, a legal hold, a research dataset before publication, the only copy of your grandmother's videos.

check_circle Tick those folders and everything else on the stick keeps working as normal. The drive stays a drive — you just stop being able to hand it to someone and hope.

delete

The drawer of old drives, given away

"Deleted" is not deleted. A £12 tool pulls files back off a formatted stick, and the one you sold last month had tax returns on it in March.

check_circle Anything you sealed first stays sealed: the copy on the drive is ciphertext, so a drive you hand over later carries nothing readable about what it used to hold. What DriveTooth does not do is wipe a drive — sealing removes plaintext, it does not overwrite the space it used to occupy, so erase hardware before it leaves the house.

What it does

Plainly

lock

One password, no account

No email, no signup, no licence key, no subscription, nothing that can be sold or hacked later. The password is only ever used on the drive in front of you.

folder_managed

It stays your normal drive

No reformatting, no giant encrypted container file, no special driver. The files are turned into ciphertext where they sit, and unlocking puts them back exactly as they were, names and dates included.

rule_folder

Lock only what matters

Tick the folders you want sealed and leave the rest plain, so the same stick can carry files for a client and files for a stranger.

history_toggle_off

It survives being yanked out

Mid-way through encrypting, a drive can be pulled. DriveTooth keeps a journal, and recovery reads what is actually on the disk and finishes or undoes the pass. It never deletes something readable on a guess.

key

Change the password in a second

Even on a 1 TB drive. Only a 32-byte key wrap is rewritten, so the ciphertext does not move and a new password takes effect immediately.

wifi_off

Works with no internet at all

On a plane, in a basement archive, in a clinic with the network cut. Nothing phones home, so nothing can be blocked, and nothing about you is ever sent anywhere.

usbThe way to open it travels with the drive next release

A locked drive is only useful if you can open it where you happen to be. So the stick carries its own copy of DriveTooth in a plain folder next to the sealed files: plug into a Windows laptop at a hotel, a Mac at a colleague's, a Linux box at the office, double-click the copy on the stick, type your password, done. Nothing gets installed on someone else's machine and nothing is left behind when you unplug.

The copy on the drive can only open the drive, and only with the password. It holds no key, remembers nothing, and is the same program you would download here.

This one is not in the download above yet: v0.1.0 needs DriveTooth installed on the machine, or run from the unzipped app. Carrying the unlocker on the stick is the next build, and this page says so rather than promising it.

How it works

For the people who want the details

After one lock, the folder tree is gone from the root of the drive. What remains is a hidden vault folder holding ciphertext, plus one small file that says a vault exists: 

# what any computer sees when you plug the drive in
/Volumes/STICK
├── .drivetooth/            # hidden on macOS, Linux and Windows
│   ├── volume.json         # format, uuid, label, KDF params, wrapped key
│   ├── manifest.dt         # encrypted: every name, path, date, mode
│   ├── journal.dt          # only while an operation is in flight
│   └── blobs/
│       ├── 9ac3f1…d2.dtc   # one file, AES-256-GCM in 1 MiB chunks
│       └── 41b70e…a8.dtc
├── DriveTooth.app / .exe   # next release: the copy that opens it, no key inside
└── readme.txt              # unticked files stay plain

Keys

Password → Argon2id (calibrated to about a second, so guessing is expensive) → password key → unwraps a random volume key. HKDF then splits that into a manifest subkey, a name subkey, and one subkey per file bound to its own random salt — no key is shared between files.

Locking and unlocking

A lock writes every blob, flushes it to the disk, re-reads and authenticates each one, and only then removes the plaintext. The key stays in memory for 15 minutes, so re-locking needs no password. Cancelling is refused past the point of no return rather than leaving a drive half-done.

The same engine ships as a command-line tool, dt_pass, for the drive that will not open in the window and the machine you would rather diagnose from a terminal.

Security, stated plainly

What someone with your drive can learn without the password

We would not want a vague promise on our own drives, so here is the real list. The code is open and the format is documented above; you can check every line of this table against it.

Without the password What is actually exposed
What is inside your files lockNothing. AES-256-GCM, and tampering with a blob makes it refuse to open.
File names, folders, where things live lockNothing. They are stored in the encrypted manifest.
When a file was last changed lockNothing. Also in the manifest.
How many files you have remove_red_eyeVisible. One opaque blob per file.
The size of each file remove_red_eyeVisible. Each blob starts with a 68-byte header that records the original length in the clear. Padding blobs to coarse size buckets is on the roadmap; until then, treat file sizes as public.
When the drive was last locked, and its label remove_red_eyeVisible. Disk and filesystem bookkeeping any computer reads to mount it.
Guessing the password warningPossible offline, forever. The vault carries a check that lets an attacker test candidates with no rate limit. Argon2id makes each try cost about a second — a long passphrase is what makes that worthless.
Hiding that you have protected data at all do_not_disturb_onNot offered. The vault folder announces itself.
  • thumb_upGood against: a lost, stolen or mislaid drive; a machine you do not control; the person who finds it and starts clicking.
  • thumb_downNot good against: a determined adversary with unlimited time and a weak password, someone watching you type it, or a computer you are already logged into (while unlocked, the key is in memory).
  • infoNot the same thing as disk encryption. FileVault, BitLocker and LUKS protect a whole machine and cannot travel as files. Use both: them for the laptop, DriveTooth for what you carry.

Platforms

Built for the drives people actually carry

Host Filesystems Notes
apple macOS 12+ APFS, exFAT, FAT32, NTFS (read), HFS+ Volumes under /Volumes; the disk your system runs from is refused.
windows Windows 10 / 11 NTFS, exFAT, FAT32, ReFS Drives A–Z; .drivetooth is marked hidden.
linux Linux ext4, exFAT, FAT32, NTFS, Btrfs, XFS /run/media, /media, /mnt.

A drive sealed on one of these opens on all of them. exFAT and FAT32 have no ownership model, so permissions are kept where the filesystem supports them and dropped where it does not — which cannot make a file any more readable.

Get it

Download it, or build it yourself

Pick the build for the computer you will use. Then, if you want the unlocker riding along in your pocket, drop the same program onto the drive you just sealed.

# or build it from source — Rust plus the Tauri v2 prerequisites
git clone https://github.com/mrnhyie/drivetooth.git
cd drivetooth
npm install
npm run dev            # development window
npm run build          # distributable bundle for this OS
npm run test:engine    # the whole engine, no window required

There is no distribution server you have to trust. The release files are the same code this page links to, and building it yourself gets you a binary with nobody's name on it but yours.

Before you rely on it

The four things people get wrong

help

The password is the whole thing

There is no reset link, no backup code, no support inbox, on purpose. Forget it and your files are ciphertext forever, including to you. Write it down somewhere physical.

touch_app

The drive still mounts normally

No operating system asks you for a password before plugging in a USB stick, and we do not fake one. The drive opens; there is simply nothing readable inside it until you type the password.

schedule

Unlocked means unlocked

While the drive is open, its names are visible to whatever the computer can see, and the key sits in memory for 15 minutes. Lock it before you leave the desk.

science

No audit yet

Standard primitives, composed carefully, covered by 84 tests — and never reviewed by anyone outside the project. If you are protecting something that must not leak, read the code or pay someone who can.
